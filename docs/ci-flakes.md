# CI flakes

A flake is a check that fails in CI although nothing it tests changed: a run of a branch that did not touch
the apps, the engine or the checks, or a repeat of a run that passed. Each one goes here, before the run is
repeated, with the run, the check, what caused it as far as the logs show, and what was changed so that it
does not come back. A flake is fixed by making the check wait for the state it reads, with a bounded time and
a message that names what it waited for, or by retrying the action that prepares the state, never by loosening
what the check asserts. A flake that comes back gets a new row, and its earlier fix is looked at again.

The emulator scripts' comments name earlier flakes where they were fixed (CI, 2026-11-11 to 2026-11-13). This
log starts on 2026-11-14.

## Defects found by flakes

A flake can show a defect of the product rather than of the check. Such a defect is fixed in the product;
the check may look once more so that the rest of it still runs, but it warns on the run each time it has to,
and the defect stays here until it is fixed.

| Found | Defect | Seen as | Status |
| --- | --- | --- | --- |
| 2026-11-12, again 2026-11-14 (run 43606775648, attempt 1) | Watch's search for the user's tool can get `ConnectException` from the tool's port while the tool listens there, and then reports it as not answering. | The chain screen says the tool does not answer and offers no user name and password, until the user looks again; `verify-chain.sh` warns ("Watch's tool search") when its one extra search was needed. | A fix on branch `tool-search` (2026-11-15): before it says that no tool answers, Watch's search tries the remembered tool's refused ports once more after one second (`ToolFinderTest` covers it, with ports shifted by the user's number and only the refused ports greeted again). The cause is not known yet: the tool listened, and a moment later it was found again. A tool restarting its proxy refuses for a moment, and Android also reports a connection its network rules stop (EPERM, EACCES) as a `ConnectException`, perhaps while the screen comes to the front; debug builds now log the error's name, so the next occurrence can settle it. Closes once `verify-chain.sh` runs in CI without the "Watch's tool search" warning. |
